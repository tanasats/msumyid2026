# ลงนามเอกสารบนเว็บ

ออกแบบร่วมกับผู้พัฒนาเมื่อ 2026-10-08 — ต่อยอดจาก `docs/design/certificates.md`

## เป้าหมาย

ผู้ใช้ลงนามเอกสาร PDF ด้วยใบรับรองของตัวเองผ่านหน้าเว็บ ทีละไฟล์หรือเป็นชุด ใช้กับ **เอกสารทั่วไป** และ **ใบประกาศจำนวนมาก** (สูงสุด 100 ไฟล์ต่อครั้ง) ไม่ต้องติดตั้งโปรแกรม

## การตัดสินใจ

| เรื่อง | ข้อสรุป |
|---|---|
| ชนิดเอกสาร | PDF เท่านั้น ลายมือชื่อแบบ PAdES ฝังในไฟล์ (ตรวจใน Adobe Acrobat/Reader ได้) |
| ที่ลงนาม | **server ลงนามด้วย key สำรอง** (signer) ผู้ใช้ยืนยันด้วย PIN ลงนามที่ตั้งเอง — ใส่ PIN ครั้งเดียวต่อชุด |
| ลักษณะลายมือชื่อ | **มองเห็นได้บนหน้า** (ค่าเริ่มต้น) และเลือกแบบมองไม่เห็นได้ — ดูหัวข้อด้านล่าง |
| ประทับเวลา | ใช้ TSA ของมหาวิทยาลัย (กำลังติดตั้ง) — URL อ่านจาก env `TSA_URL` |
| เก็บไฟล์ | ไฟล์ต้นฉบับและไฟล์ที่ลงนามแล้วเก็บใน Garage 7 วันแล้วลบอัตโนมัติ เก็บถาวรเฉพาะประวัติ (ชื่อไฟล์, SHA-256, เวลา, ใบรับรอง) — PDPA |
| ขีดจำกัด | ไม่เกิน 100 ไฟล์ต่อชุด, ไฟล์ละไม่เกิน 20 MB, รวมทั้งชุดไม่เกิน 500 MB |
| Permission | `document:sign` — ลงนามเอกสารด้วยใบรับรองของตัวเอง (ยืนยันแล้ว ยังไม่ผูกกับ role) |

## ลักษณะลายมือชื่อ (คำแนะนำ)

ใบประกาศถูกพิมพ์และส่งต่อ ผู้รับส่วนใหญ่ไม่เปิดแผงลายมือชื่อของ PDF จึงควร **มองเห็นได้**:

- **กรอบข้อความ** ที่ระบบสร้างเอง: "ลงนามดิจิทัลโดย <ชื่อไทย>", ตำแหน่ง (จาก ERP ถ้ามี), วันเวลาที่ลงนาม — ระบบสร้างจากข้อมูลในฐานข้อมูล ผู้ใช้แก้ไม่ได้ (กันการปลอมชื่อ)
- **ภาพลายเซ็น** (ไม่บังคับ): ผู้ใช้อัปโหลดภาพลายเซ็นของตัวเองครั้งเดียว (PNG พื้นโปร่งใส) ใช้วางคู่กับกรอบข้อความ
- **ตำแหน่ง:** เลือกครั้งเดียวต่อชุด แล้วใช้ตำแหน่งเดียวกันทุกไฟล์ (ใบประกาศชุดเดียวกันมาจากแม่แบบเดียวกัน)
  - ระยะแรก: ตำแหน่งสำเร็จรูป — หน้า (แรก/สุดท้าย) × มุม (ล่างซ้าย/ล่างกลาง/ล่างขวา)
  - ระยะต่อมา: ลากวางบนภาพตัวอย่างของไฟล์แรก (ต้องใช้ตัวแสดง PDF บน browser)
- ลายมือชื่อแบบมองไม่เห็นยังเลือกได้ สำหรับเอกสารที่มีช่องลงนามของตัวเองแล้ว

## ข้อควรรู้

- **กฎหมาย:** พ.ร.บ.ธุรกรรมทางอิเล็กทรอนิกส์ ม.26 — ลายมือชื่อที่เชื่อถือได้ต้องอยู่ภายใต้การควบคุมของเจ้าของ แบบ server ลงนามอาจถูกโต้แย้งเรื่องนี้ได้ ควรให้ฝ่ายกฎหมาย/DPO ตรวจก่อนเปิดใช้งานจริง
- **ใบรับรองปัจจุบัน:** EKU `emailProtection` และไม่มี `nonRepudiation` — ต้องทดสอบลงนาม PDF ด้วยใบเดิมใน Acrobat ก่อน ถ้าไม่ผ่านต้องเพิ่ม profile ใหม่ (เช่น `[ docsign ]`)
- **ความน่าเชื่อถือ:** Root CA ของมหาวิทยาลัยไม่อยู่ใน AATL ของ Adobe ผู้รับภายนอกจะเห็น "ยังไม่ทราบความถูกต้อง" จนกว่าจะติดตั้ง Root — ระบบควรมีหน้าเผยแพร่ Root/Intermediate และวิธีติดตั้ง
- **key สำรองถูกใช้บ่อยขึ้น:** ต้องมี PIN ลงนาม (hash ด้วย argon2), ล็อกชั่วคราวเมื่อใส่ PIN ผิดหลายครั้ง และ audit log ทุกเอกสาร

## ขั้นตอน

1. ผู้ใช้เลือกใบรับรองที่ใช้งานได้ และเลือก PDF 1–100 ไฟล์ → อัปโหลดเข้า Garage ผ่าน presigned URL (ตรวจชนิด/ขนาดก่อนออก URL, อัปโหลดพร้อมกันได้หลายไฟล์)
2. เลือกลักษณะและตำแหน่งลายมือชื่อ (ครั้งเดียวต่อชุด)
3. ใส่ PIN ลงนามครั้งเดียว → API สร้างชุด (batch) + งานต่อไฟล์ แล้วตอบกลับทันที
4. worker ลงนามทีละไฟล์ในเบื้องหลัง (signer ลงนาม + ขอ timestamp จาก TSA) — 100 ไฟล์ไม่ทำใน request เดียว เพราะจะ timeout
5. หน้าเว็บแสดงความคืบหน้าและสถานะรายไฟล์ (สำเร็จ/ล้มเหลวพร้อมเหตุผล เช่น PDF เสีย, มีรหัสผ่าน) ลองใหม่เฉพาะไฟล์ที่ล้มเหลวได้
6. ดาวน์โหลดทีละไฟล์ หรือรวมทั้งชุดเป็น ZIP (stream จาก Garage)

ถ้าใบรับรองถูกเพิกถอนหรือบัญชีถูกปิดระหว่างที่ชุดยังทำไม่เสร็จ → งานที่เหลือล้มเหลวทั้งหมด (ตรวจก่อนลงนามทุกไฟล์)

## ตาราง (ร่าง)

- `signing_batches`: `id`, `user_id`, `certificate_id`, `appearance` (jsonb: แบบ, หน้า, ตำแหน่ง), `status`, `expires_at`, `created_at`, `updated_at`
- `signing_jobs`: `id`, `batch_id`, `source_file_id`, `signed_file_id`, `status` (`pending`/`signing`/`signed`/`failed`), `error_code`, `document_sha256`, `signed_sha256`, `signed_at`, `created_at`, `updated_at`
- `signing_pins`: `user_id` (PK), `pin_hash`, `failed_attempts`, `locked_until`, `created_at`, `updated_at`
- `signature_images`: `user_id` (PK), `file_id`, `created_at`, `updated_at`
- ประวัติการลงนามเขียนใน `certificate_audit_logs` (action `sign`, หนึ่งแถวต่อไฟล์) — แก้/ลบไม่ได้

## Dependency ที่ต้องขออนุมัติตอนเริ่มพัฒนา

- ฝังลายมือชื่อ PAdES + ประทับเวลา: เช่น `@signpdf/signpdf` + `pdf-lib` (ใน signer)
- ทำ ZIP แบบ stream สำหรับดาวน์โหลดทั้งชุด
- (ระยะลากวาง) ตัวแสดง PDF บน browser เช่น `pdfjs-dist`

## ลำดับการพัฒนา

ทำหลังระยะ 1–3 ของ `certificates.md` (ต้องมีใบรับรองและ key สำรองก่อน)

| ระยะ | งาน |
|---|---|
| S1 | ตั้ง PIN ลงนาม + ลงนามไฟล์เดียว (มองไม่เห็น) — ใช้ทดสอบกับ Acrobat และฝ่ายกฎหมาย |
| S2 | ลงนามเป็นชุด (≤ 100 ไฟล์) + worker + สถานะรายไฟล์ + ZIP + ลบไฟล์อัตโนมัติ 7 วัน |
| S3 | ลายมือชื่อมองเห็นได้: กรอบข้อความ + ภาพลายเซ็น + ตำแหน่งสำเร็จรูป |
| S4 | ประทับเวลา (TSA) + ข้อมูลตรวจสอบระยะยาว (LTV) — เริ่มเมื่อ TSA ของมหาวิทยาลัยพร้อม |
| S5 | ลากวางตำแหน่งบนภาพตัวอย่าง |
