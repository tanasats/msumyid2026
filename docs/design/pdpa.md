# PDPA — ประกาศความเป็นส่วนตัวของ MSU Digital ID

> สถานะ: ประกาศฉบับที่ 1 มีผล **5 พฤศจิกายน 2569** — ผู้ร่าง: Claude, ผู้ตรวจ: ธนศาสตร์ สุดจริง (กรรมการ DPO ของมหาวิทยาลัย, 2026-10-26)
> **ข้อความประกาศอยู่ที่ `apps/web/src/components/privacy/PrivacyNotice.tsx` ที่เดียว** (หน้า `/privacy`) — ไฟล์นี้เก็บหลักการ รายการข้อมูล และการตัดสินใจ

## หลักการ (CLAUDE.md §18)

- ประกาศเฉพาะบริการนี้ อ้างนโยบายของมหาวิทยาลัย (https://pdpa.msu.ac.th) และประกาศสำหรับบุคลากร (https://pdpa.msu.ac.th/wp-content/uploads/2025/11/publish-staff.pdf)
- ผู้ใช้ทุกคน (รวมบัญชีรออนุมัติ/ถูกปฏิเสธ และ super_admin) ต้องกด "รับทราบ" ก่อนใช้ระบบ — เป็นการ **รับทราบ** ไม่ใช่การให้ความยินยอม
- ฐานกฎหมายหลัก: ประโยชน์โดยชอบด้วยกฎหมาย ม.24(5); log ข้อมูลจราจร: ปฏิบัติตามกฎหมาย ม.24(6) (พ.ร.บ.คอมพิวเตอร์)
- เปลี่ยนการเก็บ/เปิดเผยข้อมูล → แก้ `PrivacyNotice.tsx` + เพิ่ม `PRIVACY_NOTICE_VERSION` ให้ตรงกันทั้ง web และ `apps/api/src/services/privacy-service.ts` → ทุกคนรับทราบใหม่ → DPO ตรวจก่อน deploy
- คำร้องใช้สิทธิ์ส่งต่อ DPO ของมหาวิทยาลัย (dpo@msu.ac.th)
- ผู้พัฒนาและผู้ดูแลระบบ: ธนศาสตร์ สุดจริง หัวหน้ากลุ่มงานบริหาร สำนักคอมพิวเตอร์ (tanasat.s@msu.ac.th) — แสดงในประกาศและท้ายทุกหน้า (`SiteCredit`)

## การทำงาน

| ส่วน | รายละเอียด |
|---|---|
| ตาราง | `privacy_acknowledgements` (`user_id`, `notice_version`, `acknowledged_at`, UNIQUE คู่ user+version) — แถวเดิมคงไว้เป็นหลักฐานเมื่อเพิ่มเวอร์ชัน ไม่มีข้อมูลส่วนบุคคลจึงไม่ลบตอนลบบัญชี |
| ตรวจทุก request | `findSessionUser` คืน `privacyAcknowledged` (EXISTS บน UNIQUE index) → `requireAuth` ตอบ 403 `PRIVACY_NOTICE_REQUIRED` ก่อนตรวจสถานะบัญชี (endpoint ที่ใช้ `requireSession` เช่น `/auth/me` ยังใช้ได้) |
| รับทราบ | `POST /me/privacy-acknowledgement` `{ version }` (ต้อง login, รวมรออนุมัติ) — เวอร์ชันไม่ตรง = 409 `PRIVACY_NOTICE_OUTDATED` |
| web | `/privacy` สาธารณะ — login แล้วยังไม่รับทราบ แสดงปุ่มรับทราบ/ออกจากระบบ ทุกหน้าใช้ `redirectUnlessReady()` (ยังไม่รับทราบ → `/privacy`, ยังไม่อนุมัติ → `/pending`) |
| session | job ลบ session ที่หมดอายุทุก `SESSION_CLEANUP_INTERVAL_MS` (1 ชั่วโมง) |
| log เซิร์ฟเวอร์ | `deploy/scripts/archive-logs.sh` (cron รายวัน) + `switch_to` เก็บก่อนสลับเวอร์ชัน → `logs/<วันที่>/` เก็บ `LOG_KEEP_DAYS` = 90 วัน; nginx ตั้ง logrotate 90 วัน (`docs/deployment.md` 5.6) |

## ข้อมูลที่ระบบเก็บ (ตรวจจาก schema ณ 2026-10-26)

| กลุ่ม | ตาราง/ที่เก็บ | ข้อมูล | ระยะเวลา |
|---|---|---|---|
| บัญชี | `users` | Google sub, อีเมล, ชื่อจาก Google, ชื่อที่แสดง, URL รูปโปรไฟล์, ประเภทบัญชี, หน่วยงาน, สถานะอนุมัติ, เวลา login ล่าสุด, วันหมดอายุบัญชี/ผู้รับผิดชอบ (บัญชีหน่วยงาน) | จนลบบัญชี (ลบ = anonymize) |
| บุคลากร | `staff_profiles` (จาก ERP-HR) | รหัสบุคลากร, คำนำหน้า ชื่อ-สกุล ไทย/อังกฤษ, ตำแหน่ง, คณะ/กอง/หลักสูตร — **ไม่เก็บเบอร์โทร** | อัปเดตทุก login, ลบพร้อมบัญชี |
| นิสิต | `users` | รหัสนิสิต (ส่วนหน้า @ ของอีเมล), คณะ (จากรหัส) | จนลบบัญชี |
| ใบรับรอง | `certificates` | ชื่อ (CN), อีเมล, serial, วันเริ่ม/หมดอายุ, สถานะ/เหตุผลเพิกถอน, ตัวใบ | ลบบัญชี = ลบชื่อ/อีเมล/ตัวใบ คง serial + การเพิกถอน (เพื่อ CRL) |
| key สำรอง | `certificate_key_escrows` | private key ที่เข้ารหัส (AES + KEK ที่ signer) | ลบพร้อมบัญชี |
| คำขอใบรับรอง | `*_certificate_requests(_logs)` | เหตุผลคำขอ, ผลอนุมัติ, ผู้อนุมัติ | ลบบัญชี = ลบข้อมูลส่วนบุคคลในคำขอ |
| ลงนามเอกสาร | `signing_pins` | PIN (hash เท่านั้น) | จนลบบัญชี |
| | `signature_images` + Garage | ภาพลายมือชื่อ (ไม่ประมวลผลเพื่อระบุตัวบุคคล — ไม่ใช่ข้อมูลชีวภาพ ม.26) | จนผู้ใช้ลบเอง/ลบบัญชี |
| | `files` + Garage | ไฟล์ต้นฉบับและไฟล์ที่ลงนาม | 7 วัน |
| | `signing_batches/jobs` | ชื่อไฟล์, SHA-256 ของเอกสาร, เวลา, ผล | ตลอดอายุบัญชี (ลบชื่อไฟล์เมื่อลบบัญชี) — ยืนยัน 2026-10-26 |
| ตรวจลายมือชื่อ `/verify` | หน่วยความจำ | ไฟล์ที่อัปโหลดตรวจ — **ไม่บันทึก** | ไม่เก็บ |
| รับทราบประกาศ | `privacy_acknowledgements` | user + เวอร์ชัน + เวลา | ถาวร (ไม่มีข้อมูลส่วนบุคคล) |
| log การดำเนินการ | `user_audit_logs`, `role_change_logs`, `certificate_audit_logs`, … | ใครทำอะไรกับใคร เมื่อไร (ไม่เก็บค่าชื่อ/อีเมลใน log) | ถาวร (แก้/ลบไม่ได้) |
| session | `sessions` + cookie `msumyid_session` | hash ของ token, เวลาใช้งานล่าสุด | ลบเมื่อหมดอายุ (job) หรือ logout |
| log เซิร์ฟเวอร์ | pino (API) + nginx | method, path, header (รวม User-Agent, IP ผ่าน proxy) — ไม่ log cookie/token/query string | 90 วัน |
| backup | `deploy/scripts/backup.sh` | ฐานข้อมูลทั้งหมด | 14 วัน (`BACKUP_KEEP_DAYS`) |

ผู้รับข้อมูลภายนอก: Google (login — อยู่นอกประเทศ), ERP-HR ของมหาวิทยาลัย (ดึงข้อมูลบุคลากรด้วย token ของผู้ใช้เอง), MSU TSA (ได้รับเฉพาะค่า hash), ผู้รับเอกสาร/อีเมลที่ลงนาม (เห็นชื่อ อีเมล ใบรับรอง และภาพลายมือชื่อ — เรียกคืนไม่ได้), CRL สาธารณะ (serial + วันที่เพิกถอน ไม่มีชื่อ)

## เมื่อแก้ระบบแล้วต้องแก้ประกาศ

ตารางข้างบนต้องตรงกับ schema เสมอ — เพิ่มตาราง/คอลัมน์ที่เก็บข้อมูลส่วนบุคคล, ส่งข้อมูลให้ผู้รับใหม่ หรือเปลี่ยนระยะเก็บ → แก้ทั้งตารางนี้และ `PrivacyNotice.tsx` แล้วเพิ่มเวอร์ชัน
