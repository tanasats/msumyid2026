# แนวทางการออกแบบ UI (UI Guidelines)

เอกสารนี้กำหนดระบบสี ตัวอักษร โครงหน้าจอ และรูปแบบปฏิสัมพันธ์ของหน้าเว็บ (`apps/web`) ให้ทุกหน้าใช้เหมือนกัน
ยึดหลัก **Mobile-First** คือออกแบบสำหรับมือถือก่อน แล้วค่อยขยายไป tablet และ desktop

> สถานะ: ข้อเสนอ (2026-10-08) ยังไม่ได้นำไปใช้ในโค้ด — ไม่ใช้สีแบรนด์ของมหาวิทยาลัย (ใช้ในหลายระบบแล้ว) ระบบนี้ใช้โทนน้ำเงิน-เทาที่เป็นกลางและเน้นการอ่านง่าย

---

## 1. หลักการ

1. **ใช้มือเดียวได้** — ปุ่มที่ใช้บ่อยและปุ่มหลักของหน้าอยู่ครึ่งล่างของจอ (Thumb Zone)
2. **หนึ่งหน้า หนึ่งงานหลัก** — แต่ละหน้ามีปุ่มหลัก (primary) ได้ไม่เกิน 1 ปุ่ม
3. **อ่านง่ายก่อนสวย** — ตัวอักษรไม่เล็กกว่า 14px, เนื้อความ 16px, contrast ผ่าน WCAG AA ทุกจุด (AAA สำหรับเนื้อความหลัก)
4. **ไม่สื่อด้วยสีอย่างเดียว** — สถานะต้องมีข้อความหรือไอคอนกำกับเสมอ
5. **งานที่ย้อนกลับไม่ได้ต้องยืนยัน** — เช่น เพิกถอนใบรับรอง ต้องมีกล่องยืนยันที่บอกผลลัพธ์ชัดเจน

## 2. Typography

### 2.1 ฟอนต์

| ใช้กับ | ฟอนต์ | เหตุผล |
|---|---|---|
| ข้อความทั้งหมด (ไทย + อังกฤษ) | **Noto Sans Thai** (ใช้อยู่แล้วผ่าน `next/font/google`) | ไทยแบบไม่มีหัว ทันสมัย อ่านง่ายบนจอเล็ก มีอักษรละตินที่ออกแบบให้เข้ากัน น้ำหนัก 100–900 |
| รหัส/เลขที่ใบรับรอง, fingerprint, serial | `ui-monospace` (ฟอนต์ระบบ) | ไม่ต้องโหลดฟอนต์เพิ่ม และแยกอักษรที่หน้าตาคล้ายกัน (0/O, 1/l) ได้ |

ทางเลือกสำรองถ้าต้องการโทนทางการขึ้น: **IBM Plex Sans Thai** (ไม่มีหัวเช่นกัน) — ไม่แนะนำ Sarabun สำหรับ UI เพราะมีหัวและอ่านยากกว่าที่ขนาดเล็ก

### 2.2 สเกลตัวอักษร

ภาษาไทยมีสระและวรรณยุกต์ซ้อนบน-ล่าง จึงต้องใช้ **line-height สูงกว่าภาษาอังกฤษ** (เนื้อความ 1.7)

| ระดับ | มือถือ | Desktop (`lg:`) | Line height | Weight | Tailwind |
|---|---|---|---|---|---|
| H1 (หัวหน้า) | 24px | 30px | 1.4 | 600 | `text-2xl lg:text-3xl font-semibold leading-snug` |
| H2 (หัวส่วน) | 20px | 24px | 1.5 | 600 | `text-xl lg:text-2xl font-semibold` |
| H3 / Sub-heading | 18px | 18px | 1.5 | 600 | `text-lg font-semibold` |
| Body | 16px | 16px | 1.7 | 400 | `text-base leading-relaxed` |
| Body small / ข้อมูลรอง | 14px | 14px | 1.6 | 400 | `text-sm` |
| Label (ป้ายฟอร์ม) | 14px | 14px | 1.5 | 500 | `text-sm font-medium` |
| Button | 16px | 16px (ปุ่มเล็ก 14px) | 1.5 | 500 | `text-base font-medium` |
| Badge / Caption | 12px | 12px | 1.5 | 500 | `text-xs font-medium` (ใช้กับป้ายสั้น ๆ เท่านั้น) |

กฎเพิ่มเติม:
- **ช่องกรอก (input) ต้อง 16px ขึ้นไป** — ถ้าเล็กกว่า iOS Safari จะซูมหน้าจออัตโนมัติเมื่อแตะ
- ห้ามใช้ weight ต่ำกว่า 400 กับภาษาไทย (เส้นบางเกินไปบนจอมือถือ)
- ห้ามใช้ตัวเอียงกับภาษาไทย (Noto Sans Thai ไม่มีตัวเอียงจริง เบราว์เซอร์จะบิดเอง อ่านยาก)
- ห้ามเพิ่ม `letter-spacing` กับภาษาไทย (สระลอยแยกจากพยัญชนะ)
- ความยาวบรรทัดของเนื้อความไม่เกิน `max-w-prose` (~65 ตัวอักษร)
- ตัวเลขในตาราง/วันที่/จำนวนใช้ `tabular-nums` ให้หลักตรงกัน
- วันที่แสดงแบบไทย พ.ศ. เช่น `8 ต.ค. 2569` ผ่าน `Intl.DateTimeFormat('th-TH')`

## 3. Color Palette

ใช้สีจาก palette มาตรฐานของ Tailwind (เลี่ยงการกำหนด hex เองโดยไม่จำเป็น) และตั้งชื่อแบบ **semantic token** เพื่อให้เปลี่ยนสีทั้งระบบได้ที่เดียว

### 3.1 สีหลัก (Light mode — ค่าเริ่มต้น)

ค่าความต่าง (contrast) คำนวณตามสูตร WCAG 2.x — AA ต้อง ≥ 4.5 (ข้อความปกติ), ≥ 3 (ข้อความใหญ่/ขอบของ UI), AAA ต้อง ≥ 7

| Token | สี | Hex | ใช้กับ | Contrast |
|---|---|---|---|---|
| `canvas` | slate-50 | `#F8FAFC` | พื้นหลังหน้า | — |
| `surface` | white | `#FFFFFF` | การ์ด, header, bottom nav | — |
| `fg` | slate-900 | `#0F172A` | เนื้อความหลัก, หัวข้อ | 17.85 บน white (AAA) |
| `muted` | slate-600 | `#475569` | ข้อความรอง, คำอธิบาย | 7.58 บน white / 7.24 บน slate-50 (AAA) |
| `subtle` | slate-500 | `#64748B` | placeholder, เวลา (ข้อมูลไม่สำคัญเท่านั้น) | 4.76 (AA) |
| `line` | slate-200 | `#E2E8F0` | เส้นแบ่งการ์ด (ตกแต่ง) | — |
| `line-input` | slate-500 | `#64748B` | **ขอบช่องกรอก, checkbox** | 4.76 (ผ่าน 3:1 ของ UI) |
| `primary` | blue-700 | `#1D4ED8` | ปุ่มหลัก, ลิงก์, รายการเมนูที่เลือก | white บน blue-700 = 6.70 (AA) |
| `primary-hover` | blue-800 | `#1E40AF` | hover, ขณะกด | 8.72 (AAA) |
| `primary-soft` | blue-50 + blue-800 | `#EFF6FF` / `#1E40AF` | พื้นหลังเมนูที่เลือก, ข้อมูลแจ้ง | 8.01 (AAA) |
| `focus` | blue-600 | `#2563EB` | วงแสดง focus (2px + offset 2px) | — |

> **ข้อควรระวัง:** `slate-400` (ที่มักใช้เป็นขอบช่องกรอก) มี contrast แค่ 2.56 กับพื้นขาว **ไม่ผ่าน** เกณฑ์ 3:1 ของขอบ UI ให้ใช้ `slate-500` แทน

### 3.2 สีสถานะ

ทุกสถานะใช้คู่ "พื้นอ่อน + ตัวอักษรเข้ม + ไอคอน" เสมอ

| สถานะ | ตัวอย่างการใช้ | พื้น | ตัวอักษร/ไอคอน | Contrast |
|---|---|---|---|---|
| Success | อนุมัติแล้ว, ใบรับรองใช้งานได้ | green-50 `#F0FDF4` | green-800 `#166534` | 6.81 (AA) |
| Warning | รออนุมัติ, ใกล้หมดอายุ | amber-50 `#FFFBEB` | amber-800 `#92400E` | 6.84 (AA) |
| Danger | ปฏิเสธ, เพิกถอน, error | red-50 `#FEF2F2` | red-800 `#991B1B` | 7.60 (AAA) |
| Info | ข้อมูลแนะนำ | blue-50 `#EFF6FF` | blue-800 `#1E40AF` | 8.01 (AAA) |
| Neutral | หมดอายุ, ฉบับร่าง | slate-100 `#F1F5F9` | slate-700 `#334155` | ≥ 9 (AAA) |

ปุ่มอันตราย (danger button) ใช้ red-700 `#B91C1C` + ตัวอักษรขาว (6.47, AA)

### 3.3 Dark mode (ระยะที่ 2)

ยังไม่ต้องทำในรอบแรก แต่ให้ใช้ semantic token ตั้งแต่ต้น เพื่อเพิ่มได้ภายหลังโดยไม่ไล่แก้ทุกหน้า

| Token | Dark | Contrast |
|---|---|---|
| `canvas` / `surface` | slate-950 / slate-900 | — |
| `fg` | slate-100 | 18.41 บน slate-950 (AAA) |
| `muted` | slate-300 | 12.02 บน slate-900 (AAA) |
| `primary` | blue-400 + ตัวอักษร slate-950 | 7.93 (AAA) |

### 3.4 การตั้งค่าใน Tailwind v4 (`globals.css`)

```css
@import 'tailwindcss';

@theme {
  --font-sans: var(--font-noto-sans-thai), ui-sans-serif, system-ui, sans-serif;

  /* semantic tokens — หน้าเว็บใช้ชื่อเหล่านี้ (เช่น bg-canvas, bg-surface, text-fg, text-muted, border-line) ไม่ใช้ชื่อสีตรง ๆ */
  --color-canvas: var(--color-slate-50);
  --color-surface: var(--color-white);
  --color-fg: var(--color-slate-900);
  --color-muted: var(--color-slate-600);
  --color-subtle: var(--color-slate-500);
  --color-line: var(--color-slate-200);
  --color-line-input: var(--color-slate-500);
  --color-primary: var(--color-blue-700);
  --color-primary-hover: var(--color-blue-800);
  --color-primary-soft: var(--color-blue-50);
}
```

## 4. Mobile Layout Structure

### 4.1 หน้าระดับบน (top-level) — มี Bottom Navigation

```
┌──────────────────────────────┐
│ ▓ safe-area-top              │
│ [โลโก้] ชื่อหน้า        (รูป) │  Header 56px, sticky, bg-surface
├──────────────────────────────┤
│                              │
│  ┌────────────────────────┐  │  Content: px-4 (16px), ระยะห่างการ์ด 16px
│  │ การ์ดสรุป / สถานะ      │  │  ← ข้อมูลสำคัญที่สุดอยู่บนสุด
│  └────────────────────────┘  │
│  ┌────────────────────────┐  │
│  │ รายการ (list item 64px)│  │  ทั้งแถวกดได้ ไม่ใช่แค่ข้อความ
│  ├────────────────────────┤  │
│  │ รายการ                 │  │
│  └────────────────────────┘  │
│                    ┌──────┐  │
│                    │  +   │  │  ← FAB 56px (ถ้ามีงานสร้างใหม่เป็นงานหลัก)
├────────────────────┴──────┴──┤
│  ⌂      📄      ✉      👤   │  Bottom Nav 64px + safe-area-bottom
│ หน้าหลัก ใบรับรอง คำขอ  บัญชี │  ไอคอน 24px + ป้าย 12px เสมอ
└──────────────────────────────┘
```

### 4.2 หน้าย่อย / ฟอร์ม (task flow) — ซ่อน Bottom Navigation

```
┌──────────────────────────────┐
│ ←  ขอใบรับรองใหม่            │  Header: ปุ่มย้อนกลับ 44×44 + ชื่อหน้า
├──────────────────────────────┤
│  ขั้นที่ 1 จาก 3  ━━━──────   │  แถบความคืบหน้า (ฟอร์มหลายขั้น)
│                              │
│  ป้ายชื่อช่อง                 │
│  ┌────────────────────────┐  │  ช่องกรอก 48px, คอลัมน์เดียว
│  └────────────────────────┘  │
│  ข้อความช่วยเหลือ              │
│                              │
├──────────────────────────────┤
│ [       ดำเนินการต่อ       ] │  Sticky action bar: ปุ่มเต็มความกว้าง 48px
│ ▓ safe-area-bottom           │
└──────────────────────────────┘
```

### 4.3 ข้อกำหนด

| ส่วน | ข้อกำหนด |
|---|---|
| Header | สูง 56px, `sticky top-0`, ชื่อหน้าตัดด้วย `truncate`, ด้านขวาเป็นรูปโปรไฟล์/เมนูบัญชี |
| Content | `px-4`, ระยะห่างระหว่างส่วน 24px (`space-y-6`), เว้นท้าย `pb-24` กันเนื้อหาถูก bottom nav บัง |
| Bottom Nav | 3–5 รายการ, สูง 64px + `env(safe-area-inset-bottom)`, รายการที่เลือกใช้สี `primary` + พื้น `primary-soft` + ตัวหนา, มี `aria-current="page"` |
| เมนูตามสิทธิ์ | แสดงเฉพาะเมนูที่ผู้ใช้มี permission (ซ่อนเพื่อ UX เท่านั้น API ตรวจสิทธิ์เสมอ) — เมนูผู้ดูแลระบบรวมไว้ใต้แท็บ "บัญชี" หรือแท็บ "จัดการ" แยก |
| ความสูงจอ | ใช้ `min-h-dvh` แทน `min-h-screen` (กันแถบ address bar ของมือถือบังเนื้อหา) |
| Viewport | ตั้ง `viewportFit: 'cover'` ใน `export const viewport` ของ Next.js และ **ห้ามปิดการซูม** (`user-scalable=no`) |

> รายการเมนูใน bottom nav ข้างบนเป็นตัวอย่าง จะกำหนดจริงเมื่อฟังก์ชันของระบบชัดเจน

### 4.4 Thumb Zone

- **ครึ่งล่างของจอ (เอื้อมง่าย):** bottom nav, ปุ่มหลัก (sticky action bar / FAB), ปุ่มใน bottom sheet
- **กลางจอ:** เนื้อหาและรายการที่แตะเลือก
- **ด้านบน (เอื้อมยาก):** ข้อมูลที่อ่านอย่างเดียว, ปุ่มย้อนกลับ (มี gesture/ปุ่ม back ของระบบช่วย), เมนูบัญชีที่ใช้นาน ๆ ครั้ง
- ไม่ใช้ hamburger menu เป็นทางนำทางหลัก (ซ่อนเมนูและอยู่มุมบนที่เอื้อมยาก) — ใช้เฉพาะเป็นเมนูรองถ้าเมนูเกิน 5 รายการ

## 5. Interactive Guidelines

### 5.1 ขนาดพื้นที่แตะ

| องค์ประกอบ | ขนาดขั้นต่ำ |
|---|---|
| ปุ่มทั่วไป, ปุ่มไอคอน | **44×44px** (`size-11` / `min-h-11`) |
| ปุ่มหลัก, ช่องกรอก | **48px** สูง (`h-12`) |
| รายการในลิสต์ | 56–64px สูง ทั้งแถวกดได้ |
| ระยะห่างระหว่างเป้าหมายที่แตะได้ | ≥ 8px |

ไอคอนเล็ก (20px) ให้ขยายพื้นที่แตะด้วย padding ไม่ใช่ขยายไอคอน

### 5.2 ปุ่ม

| ประเภท | ลักษณะ | ใช้เมื่อ |
|---|---|---|
| Primary | พื้น `primary` ตัวขาว | งานหลักของหน้า (1 ปุ่มต่อหน้า) |
| Secondary | พื้นขาว ขอบ `line-input` ตัว `fg` | งานรอง เช่น ยกเลิก, ย้อนกลับ |
| Ghost / Text | ไม่มีพื้น ตัว `primary` | งานเล็ก ๆ ในการ์ด |
| Danger | พื้น red-700 ตัวขาว | ลบ, เพิกถอน, ปฏิเสธ (ใช้ในกล่องยืนยันเท่านั้น) |

สถานะของปุ่ม (ทุกปุ่มต้องมีครบ):

| สถานะ | การแสดงผล | Tailwind |
|---|---|---|
| ปกติ | ตามประเภท | — |
| Hover (เฉพาะอุปกรณ์ที่มีเมาส์) | สีเข้มขึ้น | `hover:bg-primary-hover` (Tailwind v4 ทำงานเฉพาะ `@media (hover: hover)` ให้อยู่แล้ว) |
| **กด (Pressed)** | สีเข้มขึ้น + ย่อเล็กน้อย — feedback ที่รู้สึกได้บนมือถือ | `active:bg-primary-hover active:scale-[0.98] transition` |
| Focus (คีย์บอร์ด) | วงแหวน 2px ห่าง 2px | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600` |
| Disabled | จางลง + เคอร์เซอร์ห้าม — ใช้น้อยที่สุด ควรบอกเหตุผลว่าทำไมกดไม่ได้ | `disabled:opacity-50 disabled:cursor-not-allowed` |
| Loading | แสดง spinner + เปลี่ยนข้อความ ("กำลังบันทึก...") **กันกดซ้ำ** | `aria-busy="true"` + `disabled` |

ข้อความบนปุ่มเป็น **คำกริยาที่บอกผลลัพธ์** เช่น "ส่งคำขอ", "เพิกถอนใบรับรอง" — ไม่ใช้ "ตกลง" หรือ "ยืนยัน" ลอย ๆ

การวางปุ่มคู่: มือถือเรียงแนวตั้งเต็มความกว้าง ปุ่มหลักอยู่ **ล่างสุด** (ใกล้นิ้วโป้ง) / desktop เรียงแนวนอนชิดขวา ปุ่มหลักอยู่ขวาสุด
```html
<div class="flex flex-col-reverse gap-3 sm:flex-row sm:justify-end">
  <button>ยกเลิก</button>        <!-- secondary -->
  <button>ส่งคำขอ</button>       <!-- primary -->
</div>
```

### 5.3 ฟอร์ม

- **ป้ายชื่ออยู่เหนือช่องเสมอ** ห้ามใช้ placeholder แทนป้าย (หายไปเมื่อเริ่มพิมพ์)
- คอลัมน์เดียวบนมือถือ, ช่องกรอกสูง 48px, ตัวอักษร 16px, ขอบ `line-input`
- ใช้ `type`, `inputMode`, `autoComplete` ให้ถูก เพื่อให้มือถือแสดงแป้นที่เหมาะสม (เช่น `inputMode="numeric"` สำหรับรหัสนิสิต, `type="email"`)
- ระบุช่องที่ **ไม่บังคับ** ด้วย "(ไม่บังคับ)" แทนการติด * ที่ทุกช่องบังคับ
- **ตรวจความถูกต้องเมื่อออกจากช่อง (blur) และตอนกดส่ง** ไม่ตรวจทุกครั้งที่พิมพ์
- ข้อความ error อยู่ใต้ช่อง: ไอคอน + ข้อความ red-800 + ขอบช่องเป็นสีแดง, ผูกด้วย `aria-invalid="true"` และ `aria-describedby`
- ข้อความ error บอก **วิธีแก้** เช่น "กรุณากรอกรหัสนิสิต 11 หลัก" ไม่ใช่ "ข้อมูลไม่ถูกต้อง"
- กดส่งแล้วมี error → เลื่อนและ focus ไปช่องแรกที่ผิด, ฟอร์มยาวให้มีกล่องสรุป error ด้านบน
- เกิด error จากเซิร์ฟเวอร์ต้อง **คงข้อมูลที่กรอกไว้** ห้ามล้างฟอร์ม
- ฟอร์มยาวแบ่งเป็นหลายขั้น (≤ 5–7 ช่องต่อขั้น) พร้อมแถบความคืบหน้า และหน้าทบทวนข้อมูลก่อนส่ง
- อัปโหลดไฟล์: บอกชนิดไฟล์และขนาดสูงสุดที่รับ **ก่อน** เลือกไฟล์, แสดงแถบความคืบหน้า, กดยกเลิกได้

### 5.4 การแจ้งเตือนและ feedback

| ประเภท | ใช้เมื่อ | ตำแหน่ง/พฤติกรรม |
|---|---|---|
| **Toast** | ผลลัพธ์สำเร็จที่ไม่ต้องทำอะไรต่อ ("บันทึกแล้ว") | มือถือ: ด้านล่างเหนือ bottom nav / desktop: มุมขวาล่าง, หายเองใน 4–6 วินาที, `aria-live="polite"`, ห้ามใช้กับ error |
| **Inline alert** | error หรือคำเตือนที่ผู้ใช้ต้องแก้ไข | อยู่ในหน้า ใกล้จุดที่เกี่ยวข้อง ไม่หายเอง, `role="alert"` |
| **Banner** | ข้อมูลที่กระทบทั้งระบบ (บัญชีรออนุมัติ, ใบรับรองใกล้หมดอายุ) | บนสุดของ content, ปิดได้ถ้าไม่สำคัญ |
| **กล่องยืนยัน** | งานที่ย้อนกลับไม่ได้ (เพิกถอน, ลบ, ปฏิเสธ) | มือถือ: bottom sheet / desktop: modal กลางจอ, หัวข้อเป็นคำถามที่บอกผล, ปุ่ม danger ระบุการกระทำ, focus เริ่มที่ปุ่ม "ยกเลิก" |

ตัวอย่างกล่องยืนยัน:
```
เพิกถอนใบรับรองนี้หรือไม่?
ใบรับรองจะใช้งานไม่ได้ทันทีและไม่สามารถยกเลิกการเพิกถอนได้
[ ยกเลิก ]  [ เพิกถอนใบรับรอง ]
```

### 5.5 สถานะของหน้า (ทุกหน้าต้องมี — ตาม CLAUDE.md ข้อ 14)

| สถานะ | แนวทาง |
|---|---|
| Loading | ใช้ **skeleton** ที่มีรูปร่างเหมือนเนื้อหาจริง แทน spinner กลางจอ (ลดความรู้สึกว่ารอนาน) |
| Empty | ไอคอน + ข้อความอธิบายว่าทำไมว่าง + ปุ่มให้ทำขั้นต่อไป เช่น "ยังไม่มีใบรับรอง" + [ขอใบรับรอง] |
| Error | บอกว่าเกิดอะไรขึ้นด้วยภาษาคน + ปุ่ม "ลองใหม่" ห้ามแสดงรหัส error ทางเทคนิคอย่างเดียว |
| ไม่มีสิทธิ์ | หน้า `/forbidden` บอกว่าต้องติดต่อใคร |

### 5.6 Motion และการเข้าถึง

- แอนิเมชันสั้น 150–200ms, ใช้ `motion-safe:` และเคารพ `prefers-reduced-motion`
- ทุกส่วนใช้งานด้วยคีย์บอร์ดได้ และเห็น focus ชัดเจน
- ใช้ HTML ตามความหมาย (`<button>`, `<nav>`, `<main>`, `<label>`) ก่อน ARIA
- ปุ่มไอคอนอย่างเดียวต้องมี `aria-label` ภาษาไทย
- รองรับการขยายตัวอักษร 200% โดยเนื้อหาไม่ถูกตัดหรือซ้อนกัน

## 6. Desktop Adaptation

### 6.1 Breakpoint (ค่ามาตรฐาน Tailwind)

| ช่วง | ความกว้าง | การนำทาง | Content |
|---|---|---|---|
| มือถือ (ค่าเริ่มต้น) | < 768px | Bottom Nav | คอลัมน์เดียว, `px-4` |
| Tablet (`md:`) | 768–1023px | **Navigation Rail** ด้านซ้าย กว้าง 80px (ไอคอน + ป้ายใต้ไอคอน) | 2 คอลัมน์สำหรับการ์ด, `px-6` |
| Desktop (`lg:`) | ≥ 1024px | **Sidebar** ด้านซ้าย กว้าง 256px (ไอคอน + ป้ายข้าง ๆ, ข้อมูลผู้ใช้ท้าย sidebar) | ตาราง, หลายคอลัมน์, `px-8` |
| จอกว้าง (`xl:`) | ≥ 1280px | Sidebar | Master–detail (รายการซ้าย รายละเอียดขวา) |

รายการเมนูชุดเดียวกันทุกขนาดจอ เปลี่ยนแค่รูปแบบการแสดง (bottom nav → rail → sidebar) ผู้ใช้จึงไม่ต้องเรียนรู้ใหม่

```
Desktop (lg)
┌──────────┬─────────────────────────────────────────────┐
│ [โลโก้]  │ หน้าหลัก / ใบรับรอง              (รูป) ชื่อ ▾ │ Top bar: breadcrumb + เมนูบัญชี
│          ├─────────────────────────────────────────────┤
│ ⌂ หน้าหลัก│                                             │
│ 📄 ใบรับรอง│   ┌─────────┐ ┌─────────┐ ┌─────────┐     │ การ์ดสรุป 3 คอลัมน์
│ ✉ คำขอ   │   └─────────┘ └─────────┘ └─────────┘     │
│ ⚙ จัดการ │   ┌─────────────────────────────────────┐   │
│          │   │ ตาราง                    [+ ขอใหม่] │   │ ปุ่มหลักย้ายจาก FAB มาที่หัวตาราง
│ ──────── │   └─────────────────────────────────────┘   │
│ 👤 ชื่อ   │          max-w-6xl จัดกึ่งกลาง              │
└──────────┴─────────────────────────────────────────────┘
```

### 6.2 การแปลงองค์ประกอบ

| มือถือ | Desktop |
|---|---|
| Bottom Nav | Navigation Rail (md) → Sidebar (lg) |
| FAB / Sticky action bar | ปุ่มปกติที่หัวตารางหรือท้ายฟอร์ม (ชิดขวา) |
| รายการแบบการ์ด | ตาราง (`lg:`) — ข้อมูลชุดเดียวกัน คอลัมน์ที่ไม่สำคัญซ่อนบนจอเล็ก |
| Bottom sheet | Modal กลางจอ (ยืนยัน) หรือ Dropdown (ตัวเลือก) |
| หน้าย่อยแยก (รายการ → รายละเอียด) | Master–detail บนจอเดียว (`xl:`) |
| ปุ่มเต็มความกว้าง | ปุ่มกว้างตามข้อความ (`sm:w-auto`) |
| Header ชื่อหน้า + ย้อนกลับ | Breadcrumb |

### 6.3 ความกว้างของเนื้อหา

ไม่ยืดเนื้อหาเต็มจอกว้าง:
- ฟอร์ม: `max-w-2xl`
- เนื้อความยาว (ประกาศ, คู่มือ): `max-w-prose`
- รายการ/ตาราง/dashboard: `max-w-6xl`
