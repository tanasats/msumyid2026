# แนวทางการออกแบบ UI (UI Guidelines)

เอกสารนี้กำหนดระบบสี ตัวอักษร โครงหน้าจอ และรูปแบบปฏิสัมพันธ์ของหน้าเว็บ (`apps/web`) ให้ทุกหน้าใช้เหมือนกัน
ยึดหลัก **Mobile-First** คือออกแบบสำหรับมือถือก่อน แล้วค่อยขยายไป tablet และ desktop

> สถานะ: ใช้งานจริงแล้ว (ปรับปรุง 2026-10-22) — แนว **เป็นทางการ น่าเชื่อถือ** โทน "หมึกและกระดาษ": กระดาษขาว · หมึกเกือบดำ · หมึกน้ำเงินคราม (แทนแนว Luxury ทอง/น้ำตาลเดิม)
> มีโหมดสว่าง/มืด (หัวข้อ 3) และผู้ใช้เลือกขนาดตัวอักษรได้ 4 ระดับ (หัวข้อ 2.6) — ไม่ใช้สีแบรนด์ของมหาวิทยาลัย (ใช้ในหลายระบบแล้ว)

---

## 1. หลักการ

1. **ใช้มือเดียวได้** — ปุ่มที่ใช้บ่อยและปุ่มหลักของหน้าอยู่ครึ่งล่างของจอ (Thumb Zone)
2. **หนึ่งหน้า หนึ่งงานหลัก** — แต่ละหน้ามีปุ่มหลัก (primary) ได้ไม่เกิน 1 ปุ่ม
3. **อ่านง่ายก่อนสวย** — ตัวอักษรไม่เล็กกว่า 14px (ป้ายสั้น 12px), เนื้อความ 16px, contrast ผ่าน WCAG AA ทุกจุด (AAA สำหรับเนื้อความหลัก) ทั้งโหมดสว่างและมืด
4. **ไม่สื่อด้วยสีอย่างเดียว** — สถานะต้องมีข้อความหรือไอคอนกำกับเสมอ
5. **งานที่ย้อนกลับไม่ได้ต้องยืนยัน** — เช่น เพิกถอนใบรับรอง ต้องมีกล่องยืนยันที่บอกผลลัพธ์ชัดเจน
6. **ทางการด้วยความเรียบ** — ความน่าเชื่อถือมาจากโครงที่เป็นระเบียบ เส้นขอบชัด ลำดับชั้นตัวอักษร และสีหลักเพียงสีเดียว ไม่ใช่การตกแต่ง — ลายนิรภัยใช้เฉพาะหน้าสาธารณะ

## 2. Typography

หลัก: **IBM Plex Sans Thai Looped** (เนื้อหา) + **Mornamchi** (หัวข้อ — ฟอนต์อัตลักษณ์ของมหาวิทยาลัย) + **IBM Plex Mono** (รหัส) หัวข้อแสดงอัตลักษณ์ ส่วนเนื้อหาใช้ไทยมีหัวเพื่ออ่านง่าย ใช้น้ำหนัก 400 / 500 / 600 เป็นหลัก

### 2.1 ฟอนต์

| บทบาท | ฟอนต์ | Utility | ใช้กับ | เหตุผล |
|---|---|---|---|---|
| เนื้อหา (ค่าเริ่มต้น) | **IBM Plex Sans Thai Looped** | `font-sans` | ทุกข้อความที่ไม่ใช่หัวข้อ: เนื้อความ, ป้ายฟอร์ม, ปุ่ม, ช่องกรอก, เมนู, ป้ายสถานะ | ไทยมีหัว (ทางการ อ่านง่ายสำหรับทุกวัย) ออกแบบสำหรับ UI บนจอ ละติน/ตัวเลขสูงพอดีกับไทย (Sarabun เดิมละตินเล็กกว่าไทยชัดเจน) — โหลดน้ำหนัก 400/500/600/700 |
| หัวข้อ (display) | **Mornamchi** (ไฟล์ใน repo: `apps/web/src/fonts/`, ต้นฉบับ `docs/Font - Mornamchi/`) | `font-display` | ชื่อระบบ, h1, หัวข้อส่วน (h2), หัวข้อของสถานะทั้งหน้า | ฟอนต์อัตลักษณ์ที่มหาวิทยาลัยมหาสารคามออกแบบ (แบบเดียวกับตัวอักษรในโลโก้) ไทยไม่มีหัว — มีเฉพาะ Regular 400 / Bold 700: `font-semibold` ได้ Bold, `font-medium` ได้ Regular **ห้ามใช้กับเนื้อความ ปุ่ม ฟอร์ม** (ไม่มีน้ำหนัก 500/600 ให้แยกลำดับชั้น และไทยไม่มีหัวอ่านยากกว่าในข้อความยาว) |
| รหัส | **IBM Plex Mono** | `font-mono` | serial, fingerprint, รหัสอ้างอิง | ตระกูลเดียวกับเนื้อหา แยก 0/O, 1/l ชัด หน้าตาเหมือนกันทุกระบบปฏิบัติการ — โหลด 400/500 (ละตินเท่านั้น) |

- โหลดผ่าน `next/font/google` ใน `apps/web/src/app/layout.tsx` (`--font-plex-sans-thai`, `--font-plex-mono`) และ `next/font/local` (`--font-mornamchi`) และผูกเป็น `--font-sans` / `--font-display` / `--font-mono` ใน `globals.css` (`@theme inline`)
- ทั้งสองฟอนต์โหลดเฉพาะน้ำหนักใน `weight` — ใช้น้ำหนักใหม่ต้องเพิ่มที่นั่นด้วย ไม่เช่นนั้น browser จะทำตัวหนาปลอม
- `display: 'swap'` — ระหว่างโหลดแสดงฟอนต์ระบบก่อน ข้อความไม่หายไป
- **ห้ามเพิ่มฟอนต์ตระกูลอื่น** โดยไม่ปรับเอกสารนี้ และห้ามใช้ `font-display` กับเนื้อความยาว ปุ่ม ช่องกรอก ตาราง หรือข้อความเล็กกว่า 16px (ยกเว้นชื่อระบบใน sidebar)

### 2.2 ลำดับชั้นตัวอักษร (ตามที่ใช้ในโค้ด)

ภาษาไทยมีสระและวรรณยุกต์ซ้อนบน-ล่าง จึงใช้ **line-height สูงกว่าภาษาอังกฤษ** (เนื้อความ 1.7)
ขนาดในตารางคือขนาด "ปกติ" — ผู้ใช้เลือก เล็ก/ใหญ่/ใหญ่มาก ได้ และทุกระดับขยายตามสัดส่วน (หัวข้อ 2.6)

| ระดับ | ตัวอย่างที่ใช้ | ขนาด | Weight | Tailwind |
|---|---|---|---|---|
| Hero (h1 ของหน้าเดี่ยว) | การ์ด "เข้าสู่ระบบ" | 24px | 600 | `font-display text-2xl leading-snug font-semibold` |
| ชื่อหน้า (h1 ใน header) | "ใบรับรองของฉัน", "จัดการผู้ใช้" | 18px | 600 | `font-display text-lg font-semibold truncate` (`PageShell` ทำให้) |
| หัวข้อสถานะทั้งหน้า | "ยังไม่มีใบรับรอง", "ไม่มีสิทธิ์เข้าถึง" | 20px | 600 | `font-display text-xl font-semibold` (`StatusState`) |
| คำทักทาย/หัวข้อเด่น | "สวัสดี …" หน้าหลัก | 20 → 24px (`lg:`) | 600 | `font-display text-xl font-semibold lg:text-2xl` |
| หัวข้อส่วน (h2) | "การแสดงผล", "ข้อมูลในใบรับรอง" | 18px | 600 | `font-display text-lg font-semibold` |
| หัวข้อย่อย (h3) | "ขนาดตัวอักษร" | 14px | 500 | `text-sm font-medium` (sans) |
| ชื่อรายการ/การ์ด | ชื่อในใบรับรอง, ชื่อผู้ใช้ในรายการ | 16px | 600 | `font-semibold` (sans) |
| เนื้อความ | คำอธิบาย, ข้อความในหน้า | 16px | 400 | `text-base leading-relaxed` |
| ข้อมูลรอง | อีเมลใต้ชื่อ, คำอธิบายใต้หัวข้อ | 14px | 400 | `text-sm text-muted` |
| ป้ายฟอร์ม | "รหัสผ่าน", "เหตุผล" | 14px | 500 | `text-sm font-medium` |
| ปุ่ม | ปุ่มหลัก / ปุ่มเล็ก | 16px / 14px | 500 | `text-base font-medium` / `text-sm` (`Button`) |
| ป้ายสถานะ/caption | "ใช้งานได้", "นำเข้าจากระบบเดิม" | 12px | 500 | `text-xs font-medium` — ป้ายสั้นเท่านั้น |
| รหัส | serial, fingerprint | 12px | 400 | `font-mono text-xs break-all` |

**ชื่อระบบ** "MSU Digital ID": `font-display font-semibold tracking-wide` + บรรทัดล่าง "มหาวิทยาลัยมหาสารคาม" `text-xs text-muted` (component `BrandName` ใน `PageShell.tsx`)

### 2.3 สีของตัวอักษร

ใช้ token เท่านั้น (ค่าเต็มและ contrast ทั้งสองโหมดดูหัวข้อ 3.1)

| Token | ใช้กับ | สว่าง / มืด | Contrast |
|---|---|---|---|
| `text-fg` | เนื้อความหลัก หัวข้อ | หมึกเกือบดำ / ขาวอมเทา | 17.3 / 14.6 (AAA) |
| `text-muted` | ข้อความรอง คำอธิบาย | เทาหมึก / เทาอ่อน | 7.6 / 8.2 (AAA) |
| `text-subtle` | placeholder ข้อมูลไม่สำคัญเท่านั้น | เทา | 5.4 / 5.5 (AA) |
| `text-accent` | ลิงก์ ข้อความเน้น | น้ำเงินคราม / น้ำเงินอ่อน | 9.1 / 9.8 |
| `text-{status}-fg` | ข้อความในป้าย/กล่องสถานะ, error ใต้ช่องกรอก (`text-danger-fg`) | ตามสถานะ | ≥ 6.6 |

- โหมดมืดใช้ขาวอมเทา (`#E7EAF3`) ไม่ใช่ขาวล้วน — ลดแสงจ้าบนพื้นน้ำเงินเข้ม อ่านนานไม่ล้าตา
- **ห้ามใช้ `text-ornament` กับข้อความ** (contrast 2.9 บนพื้นสว่าง) ใช้กับลายตกแต่ง/เส้นเท่านั้น
- ลิงก์ในเนื้อความ: `text-accent underline` (หรือ `hover:underline` ในรายการ) — ไม่สื่อด้วยสีอย่างเดียว

### 2.4 กฎของภาษาไทย

- **ช่องกรอก (input) ต้อง 16px ขึ้นไป** — ถ้าเล็กกว่า iOS Safari ซูมหน้าจออัตโนมัติเมื่อแตะ (ขนาด "เล็ก" ระบบบังคับไว้ให้แล้ว)
- ห้ามใช้ weight ต่ำกว่า 400 (เส้นบางเกินไปบนจอมือถือ โดยเฉพาะโหมดมืด) และใช้ 700 ขึ้นไปเท่าที่จำเป็น — ความเป็นทางการมาจากน้ำหนักที่พอดี
- ห้ามใช้ตัวเอียง (ทั้งสองฟอนต์ไม่มีตัวเอียงไทยจริง เบราว์เซอร์จะบิดเอง อ่านยาก)
- **ห้ามปรับ `letter-spacing` (tracking) กับภาษาไทย** — สระลอยแยกจากพยัญชนะ; `tracking-wide` ใช้ได้เฉพาะข้อความภาษาอังกฤษล้วน (ชื่อระบบ)
- ห้ามใช้ตัวพิมพ์ใหญ่ทั้งคำ (`uppercase`) กับหัวข้อที่มีภาษาไทยปน
- ความยาวบรรทัดของเนื้อความไม่เกิน `max-w-prose` (~65 ตัวอักษร); ข้อความยาวที่ตัดคำไม่ได้ (อีเมล, serial) ใช้ `break-all` / ชื่อใช้ `break-words` หรือ `truncate`

### 2.5 ตัวเลข วันที่ และรหัส

- ตัวเลขในตาราง/วันที่/จำนวน: `tabular-nums` ให้หลักตรงกัน
- วันที่แบบไทย พ.ศ. เช่น `8 ต.ค. 2569` ผ่าน `Intl.DateTimeFormat('th-TH', { dateStyle: 'medium' })`
- serial/fingerprint: `font-mono text-xs break-all` ตัวพิมพ์เล็กตามที่เก็บในระบบ

### 2.6 ขนาดตัวอักษรที่ผู้ใช้เลือกได้

ผู้ใช้เลือกได้ 4 ระดับที่หน้า "บัญชีของฉัน" → "การแสดงผล" (cookie `msumyid_text_size` → `data-text-size` ที่ `<html>` ตั้งแต่ฝั่ง server ไม่กระพริบ — `components/TextSizeSwitcher.tsx`, `lib/theme.ts`)

| ระดับ | ค่า | ขนาดฐาน (`html`) | เนื้อความ | ชื่อหน้า / หัวข้อส่วน |
|---|---|---|---|---|
| เล็ก | `small` | 87.5% | 14px | 15.75px |
| ปกติ (ค่าเริ่มต้น) | `normal` | 100% | 16px | 18px |
| ใหญ่ | `large` | 112.5% | 18px | 20.25px |
| ใหญ่มาก | `xlarge` | 125% | 20px | 22.5px |

- ใช้ % จึงคูณกับขนาดที่ผู้ใช้ตั้งไว้ใน browser/ระบบปฏิบัติการ (ไม่ทับการตั้งค่าเพื่อการเข้าถึงของเครื่อง)
- ทั้งเว็บใช้หน่วย `rem` ของ Tailwind ตัวอักษร ระยะห่าง และพื้นที่แตะจึงขยายตามกัน — **ห้ามกำหนดขนาดเป็น px** ยกเว้นที่ตั้งใจไม่ให้ขยาย (ตัวอย่าง "ก" ในปุ่มเลือกขนาด)
- ขนาด "เล็ก": ช่องกรอกยังคง ≥ 16px (`max(1rem, 16px)` ใน `globals.css`)
- ทดสอบหน้าใหม่ที่ "ใหญ่มาก" บนจอ 360px ให้เนื้อหาไม่ล้นหรือซ้อนกัน (`min-w-0`, `truncate`, `break-words`)

### 2.7 ตัวอย่าง

```tsx
// ✅ หัวข้อส่วน font-display + คำอธิบายสีรอง
<h2 className="font-display text-lg font-semibold">การแสดงผล</h2>
<p className="mt-1 text-sm text-muted">เลือกโหมดสว่างหรือมืด</p>

// ✅ ลิงก์สี accent (อ่านได้ทั้งสองโหมด)
<Link href="/admin/users/1" className="font-medium text-accent hover:underline">สมชาย ใจดี</Link>

// ❌ font-display กับเนื้อความ/ปุ่ม, ช่องไฟกับภาษาไทย, สีตกแต่งกับข้อความ, ขนาดเป็น px
<p className="font-display">…</p>
<h1 className="tracking-tight">ใบรับรองของฉัน</h1>
<span className="text-ornament">ลิงก์</span>
<p className="text-[15px]">…</p>
```

## 3. Color Palette — หมึกและกระดาษ (Ink & Paper)

แนวทาง **เป็นทางการ น่าเชื่อถือ**: อ้างอิงเอกสารราชการและเอกสารสำคัญ — กระดาษขาว ตัวอักษรหมึกเกือบดำ และ **สีหมึกน้ำเงินคราม** (สีหมึกที่ใช้ลงนามเอกสาร) เป็นสีหลักเพียงสีเดียว ไม่ใช้ navy ทั่วไป และไม่ใช้สีแบรนด์ของมหาวิทยาลัย (ใช้ในหลายระบบแล้ว)

- **สว่าง "หมึกและกระดาษ":** พื้นเทาเย็นอ่อน การ์ดขาว ตัวอักษรหมึกเกือบดำ ปุ่มหลักน้ำเงินคราม ลิงก์น้ำเงิน
- **มืด "หมึกยามค่ำ":** พื้นน้ำเงินหมึกเข้ม การ์ดน้ำเงินเทา ตัวอักษรขาวอมเทา ปุ่มหลักน้ำเงินอ่อน ตัวอักษรเข้ม
- สีสถานะเป็นโทนเข้มแบบหมึกพิมพ์ (เขียวป่า / อำพัน / แดงชาด / น้ำเงินเหล็ก) — ใช้คู่ "พื้นอ่อน + ตัวเข้ม + ไอคอน" เสมอ (ไม่สื่อด้วยสีอย่างเดียว)
- รูปทรง: มุมโค้งน้อย (ปรับสเกล `rounded-lg/xl/2xl` ใน `@theme` เป็น 6/8/12px — component ไม่ต้องแก้) เงาบางมาก ใช้เส้นขอบแยกส่วน

### 3.1 Semantic tokens

หน้าเว็บใช้ **ชื่อ token เท่านั้น** (`bg-surface`, `text-muted`, `bg-danger-soft` …) ห้ามใช้สี palette ของ Tailwind ตรง ๆ (`bg-slate-100`, `text-red-800`, `text-white`) — ESLint ตรวจให้ (กฎ `no-restricted-syntax` ใน `eslint.config.mjs`)
ค่าจริงอยู่ที่ `apps/web/src/app/globals.css` ที่เดียว contrast คำนวณตาม WCAG 2.x กับ `surface` (AA ≥ 4.5 ข้อความ, ≥ 3 ขอบ UI, AAA ≥ 7)

| Token (utility) | ใช้กับ | Light | Dark | Contrast L / D |
|---|---|---|---|---|
| `canvas` | พื้นหลังหน้า | `#F3F5F8` | `#0B1020` | — |
| `surface` | การ์ด, header, bottom nav | `#FFFFFF` | `#121830` | — |
| `surface-hover` | hover, หัวตาราง, ช่องที่ปิดใช้ | `#EDF0F5` | `#1B2340` | — |
| `skeleton` | skeleton ตอนโหลด, รูปโปรไฟล์ที่ยังไม่โหลด | `#E2E6ED` | `#222B4A` | — |
| `fg` | เนื้อความหลัก, หัวข้อ | `#121A2E` | `#E7EAF3` | 17.3 / 14.6 |

### 3.3 โหมดสว่าง/มืด

- ค่าเริ่มต้น **ตามระบบของเครื่อง** (`prefers-color-scheme`) — ผู้ใช้เลือกบังคับได้ที่หน้า "บัญชีของฉัน" (และปุ่มไอคอนใน header ของหน้า login / รออนุมัติ)
- เก็บใน cookie `msumyid_theme` (`system` / `light` / `dark`, 1 ปี) — root layout อ่านแล้วใส่ `data-theme` ที่ `<html>` ตั้งแต่ฝั่ง server จึง **ไม่กระพริบ** และไม่ต้องใช้สคริปต์ inline (`lib/theme.ts`, `lib/theme-server.ts`, `components/ThemeSwitcher.tsx`)
- variant `dark` (กำหนดด้วย `@custom-variant` ใน globals.css) = บังคับมืด หรือ ตามระบบที่เป็นมืดและไม่ได้บังคับสว่าง — ใช้ได้ทั้ง `@variant dark { … }` ใน CSS และ `dark:` ใน utility (ควรใช้ token แทน `dark:` เกือบทุกกรณี)
- แถบ browser บนมือถือ (`themeColor` ใน `layout.tsx`) = สี `surface` ของแต่ละโหมด

## 5. Interactive Guidelines

### 5.1 ขนาดพื้นที่แตะ

| องค์ประกอบ | ขนาดขั้นต่ำ |
|---|---|
| ปุ่มทั่วไป, ปุ่มไอคอน | **44×44px** (`size-11` / `min-h-11`) |
| ปุ่มหลัก, ช่องกรอก | **48px** สูง (`h-12`) |
| รายการในลิสต์ | 56–64px สูง ทั้งแถวกดได้ |
| ระยะห่างระหว่างเป้าหมายที่แตะได้ | ≥ 8px |

ไอคอนเล็ก (20px) ให้ขยายพื้นที่แตะด้วย padding ไม่ใช่ขยายไอคอน

### 5.2 ปุ่ม

| ประเภท | ลักษณะ | ใช้เมื่อ |
|---|---|---|
| Primary | พื้น `primary` ตัวขาว | งานหลักของหน้า (1 ปุ่มต่อหน้า) |
| Secondary | พื้นขาว ขอบ `line-input` ตัว `fg` | งานรอง เช่น ยกเลิก, ย้อนกลับ |
| Ghost / Text | ไม่มีพื้น ตัว `primary` | งานเล็ก ๆ ในการ์ด |
| Danger | พื้น red-700 ตัวขาว | ลบ, เพิกถอน, ปฏิเสธ (ใช้ในกล่องยืนยันเท่านั้น) |

สถานะของปุ่ม (ทุกปุ่มต้องมีครบ):

| สถานะ | การแสดงผล | Tailwind |
|---|---|---|
| ปกติ | ตามประเภท | — |
| Hover (เฉพาะอุปกรณ์ที่มีเมาส์) | สีเข้มขึ้น | `hover:bg-primary-hover` (Tailwind v4 ทำงานเฉพาะ `@media (hover: hover)` ให้อยู่แล้ว) |
| **กด (Pressed)** | สีเข้มขึ้น + ย่อเล็กน้อย — feedback ที่รู้สึกได้บนมือถือ | `active:bg-primary-hover active:scale-[0.98] transition` |
| Focus (คีย์บอร์ด) | วงแหวน 2px ห่าง 2px | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600` |
| Disabled | จางลง + เคอร์เซอร์ห้าม — ใช้น้อยที่สุด ควรบอกเหตุผลว่าทำไมกดไม่ได้ | `disabled:opacity-50 disabled:cursor-not-allowed` |
| Loading | แสดง spinner + เปลี่ยนข้อความ ("กำลังบันทึก...") **กันกดซ้ำ** | `aria-busy="true"` + `disabled` |

ข้อความบนปุ่มเป็น **คำกริยาที่บอกผลลัพธ์** เช่น "ส่งคำขอ", "เพิกถอนใบรับรอง" — ไม่ใช้ "ตกลง" หรือ "ยืนยัน" ลอย ๆ

การวางปุ่มคู่: มือถือเรียงแนวตั้งเต็มความกว้าง ปุ่มหลักอยู่ **ล่างสุด** (ใกล้นิ้วโป้ง) / desktop เรียงแนวนอนชิดขวา ปุ่มหลักอยู่ขวาสุด
```html
<div class="flex flex-col-reverse gap-3 sm:flex-row sm:justify-end">
  <button>ยกเลิก</button>        <!-- secondary -->
  <button>ส่งคำขอ</button>       <!-- primary -->
</div>
```

### 5.3 ฟอร์ม

- **ป้ายชื่ออยู่เหนือช่องเสมอ** ห้ามใช้ placeholder แทนป้าย (หายไปเมื่อเริ่มพิมพ์)
- คอลัมน์เดียวบนมือถือ, ช่องกรอกสูง 48px, ตัวอักษร 16px, ขอบ `line-input`
- ใช้ `type`, `inputMode`, `autoComplete` ให้ถูก เพื่อให้มือถือแสดงแป้นที่เหมาะสม (เช่น `inputMode="numeric"` สำหรับรหัสนิสิต, `type="email"`)
- ระบุช่องที่ **ไม่บังคับ** ด้วย "(ไม่บังคับ)" แทนการติด * ที่ทุกช่องบังคับ
- **ตรวจความถูกต้องเมื่อออกจากช่อง (blur) และตอนกดส่ง** ไม่ตรวจทุกครั้งที่พิมพ์
- ข้อความ error อยู่ใต้ช่อง: ไอคอน + ข้อความ red-800 + ขอบช่องเป็นสีแดง, ผูกด้วย `aria-invalid="true"` และ `aria-describedby`
- ข้อความ error บอก **วิธีแก้** เช่น "กรุณากรอกรหัสนิสิต 11 หลัก" ไม่ใช่ "ข้อมูลไม่ถูกต้อง"
- กดส่งแล้วมี error → เลื่อนและ focus ไปช่องแรกที่ผิด, ฟอร์มยาวให้มีกล่องสรุป error ด้านบน
- เกิด error จากเซิร์ฟเวอร์ต้อง **คงข้อมูลที่กรอกไว้** ห้ามล้างฟอร์ม
- ฟอร์มยาวแบ่งเป็นหลายขั้น (≤ 5–7 ช่องต่อขั้น) พร้อมแถบความคืบหน้า และหน้าทบทวนข้อมูลก่อนส่ง
- อัปโหลดไฟล์: บอกชนิดไฟล์และขนาดสูงสุดที่รับ **ก่อน** เลือกไฟล์, แสดงแถบความคืบหน้า, กดยกเลิกได้

### 5.4 การแจ้งเตือนและ feedback

| ประเภท | ใช้เมื่อ | ตำแหน่ง/พฤติกรรม |
|---|---|---|
| **Toast** | ผลลัพธ์สำเร็จที่ไม่ต้องทำอะไรต่อ ("บันทึกแล้ว") | มือถือ: ด้านล่างเหนือ bottom nav / desktop: มุมขวาล่าง, หายเองใน 4–6 วินาที, `aria-live="polite"`, ห้ามใช้กับ error |
| **Inline alert** | error หรือคำเตือนที่ผู้ใช้ต้องแก้ไข | อยู่ในหน้า ใกล้จุดที่เกี่ยวข้อง ไม่หายเอง, `role="alert"` |
| **Banner** | ข้อมูลที่กระทบทั้งระบบ (บัญชีรออนุมัติ, ใบรับรองใกล้หมดอายุ) | บนสุดของ content, ปิดได้ถ้าไม่สำคัญ |
| **กล่องยืนยัน** | งานที่ย้อนกลับไม่ได้ (เพิกถอน, ลบ, ปฏิเสธ) | มือถือ: bottom sheet / desktop: modal กลางจอ, หัวข้อเป็นคำถามที่บอกผล, ปุ่ม danger ระบุการกระทำ, focus เริ่มที่ปุ่ม "ยกเลิก" |

ตัวอย่างกล่องยืนยัน:
```
เพิกถอนใบรับรองนี้หรือไม่?
ใบรับรองจะใช้งานไม่ได้ทันทีและไม่สามารถยกเลิกการเพิกถอนได้
[ ยกเลิก ]  [ เพิกถอนใบรับรอง ]
```

### 5.5 สถานะของหน้า (ทุกหน้าต้องมี — ตาม CLAUDE.md ข้อ 14)

| สถานะ | แนวทาง |
|---|---|
| Loading | ใช้ **skeleton** ที่มีรูปร่างเหมือนเนื้อหาจริง แทน spinner กลางจอ (ลดความรู้สึกว่ารอนาน) |
| Empty | ไอคอน + ข้อความอธิบายว่าทำไมว่าง + ปุ่มให้ทำขั้นต่อไป เช่น "ยังไม่มีใบรับรอง" + [ขอใบรับรอง] |
| Error | บอกว่าเกิดอะไรขึ้นด้วยภาษาคน + ปุ่ม "ลองใหม่" ห้ามแสดงรหัส error ทางเทคนิคอย่างเดียว |
| ไม่มีสิทธิ์ | หน้า `/forbidden` บอกว่าต้องติดต่อใคร |

### 5.6 Motion และการเข้าถึง

- แอนิเมชันสั้น 150–200ms, ใช้ `motion-safe:` และเคารพ `prefers-reduced-motion`
- ทุกส่วนใช้งานด้วยคีย์บอร์ดได้ และเห็น focus ชัดเจน
- ใช้ HTML ตามความหมาย (`<button>`, `<nav>`, `<main>`, `<label>`) ก่อน ARIA
- ปุ่มไอคอนอย่างเดียวต้องมี `aria-label` ภาษาไทย
- รองรับการขยายตัวอักษร 200% โดยเนื้อหาไม่ถูกตัดหรือซ้อนกัน

## 6. Desktop Adaptation

### 6.1 Breakpoint (ค่ามาตรฐาน Tailwind)

| ช่วง | ความกว้าง | การนำทาง | Content |
|---|---|---|---|
| มือถือ (ค่าเริ่มต้น) | < 768px | Bottom Nav | คอลัมน์เดียว, `px-4` |
| Tablet (`md:`) | 768–1023px | **Navigation Rail** ด้านซ้าย กว้าง 80px (ไอคอน + ป้ายใต้ไอคอน) | 2 คอลัมน์สำหรับการ์ด, `px-6` |
| Desktop (`lg:`) | ≥ 1024px | **Sidebar** ด้านซ้าย กว้าง 256px (ไอคอน + ป้ายข้าง ๆ, ข้อมูลผู้ใช้ท้าย sidebar) | ตาราง, หลายคอลัมน์, `px-8` |
| จอกว้าง (`xl:`) | ≥ 1280px | Sidebar | Master–detail (รายการซ้าย รายละเอียดขวา) |

รายการเมนูชุดเดียวกันทุกขนาดจอ เปลี่ยนแค่รูปแบบการแสดง (bottom nav → rail → sidebar) ผู้ใช้จึงไม่ต้องเรียนรู้ใหม่

```
Desktop (lg)
┌──────────┬─────────────────────────────────────────────┐
│ [โลโก้]  │ หน้าหลัก / ใบรับรอง              (รูป) ชื่อ ▾ │ Top bar: breadcrumb + เมนูบัญชี
│          ├─────────────────────────────────────────────┤
│ ⌂ หน้าหลัก│                                             │
│ 📄 ใบรับรอง│   ┌─────────┐ ┌─────────┐ ┌─────────┐     │ การ์ดสรุป 3 คอลัมน์
│ ✉ คำขอ   │   └─────────┘ └─────────┘ └─────────┘     │
│ ⚙ จัดการ │   ┌─────────────────────────────────────┐   │
│          │   │ ตาราง                    [+ ขอใหม่] │   │ ปุ่มหลักย้ายจาก FAB มาที่หัวตาราง
│ ──────── │   └─────────────────────────────────────┘   │
│ 👤 ชื่อ   │          max-w-6xl จัดกึ่งกลาง              │
└──────────┴─────────────────────────────────────────────┘
```

### 6.2 การแปลงองค์ประกอบ

| มือถือ | Desktop |
|---|---|
| Bottom Nav | Navigation Rail (md) → Sidebar (lg) |
| FAB / Sticky action bar | ปุ่มปกติที่หัวตารางหรือท้ายฟอร์ม (ชิดขวา) |
| รายการแบบการ์ด | ตาราง (`lg:`) — ข้อมูลชุดเดียวกัน คอลัมน์ที่ไม่สำคัญซ่อนบนจอเล็ก |
| Bottom sheet | Modal กลางจอ (ยืนยัน) หรือ Dropdown (ตัวเลือก) |
| หน้าย่อยแยก (รายการ → รายละเอียด) | Master–detail บนจอเดียว (`xl:`) |
| ปุ่มเต็มความกว้าง | ปุ่มกว้างตามข้อความ (`sm:w-auto`) |
| Header ชื่อหน้า + ย้อนกลับ | Breadcrumb |

### 6.3 ความกว้างของเนื้อหา

ไม่ยืดเนื้อหาเต็มจอกว้าง:
- ฟอร์ม: `max-w-2xl`
- เนื้อความยาว (ประกาศ, คู่มือ): `max-w-prose`
- รายการ/ตาราง/dashboard: `max-w-6xl`

## 8. Checklist ก่อนส่งงานหน้าใหม่

- [ ] ทดสอบที่ความกว้าง 360px (มือถือเล็ก), 768px และ 1280px **ทั้งโหมดสว่างและมืด** และที่ขนาดตัวอักษร "ใหญ่มาก"
- [ ] พื้นที่แตะทุกจุด ≥ 44×44px และปุ่มหลักอยู่ในครึ่งล่างของจอบนมือถือ
- [ ] ข้อความทุกจุด contrast ≥ 4.5:1, ขอบช่องกรอก ≥ 3:1
- [ ] ช่องกรอก 16px ขึ้นไป มีป้ายชื่อ และ error บอกวิธีแก้
- [ ] มีสถานะ loading / empty / error ครบ
- [ ] ปุ่มที่ส่งข้อมูลกันกดซ้ำ และงานที่ย้อนกลับไม่ได้มีกล่องยืนยัน
- [ ] ใช้งานด้วยคีย์บอร์ดได้ และเห็น focus ชัดเจน
- [ ] ใช้ semantic token (หัวข้อ 3) ไม่ใช้ชื่อสีตรง ๆ — `pnpm lint` ต้องผ่าน; `ornament` ใช้ตกแต่งเท่านั้น
